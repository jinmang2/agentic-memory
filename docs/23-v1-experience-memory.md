# v1 — 코딩 에이전트의 경험 메모리: 조각이 이어지는 순서와 지금까지의 증거 (2026-09-05)

v1의 정본 서술. 이 문서는 조사·측정·구현이 **왜 이 순서로 이어졌는지**를 한 줄로 잇고, 각 고리의 근거 문서·커밋·수치를 붙인다.
수치는 web small 240문항 4아암(2026-09-04)과 raw+explorer 분산 재실행(2026-09-05)까지다. 전체 그림과 현재 위치는 내부
지도(`docs/_internal/v1-map.html`, 비커밋)에 같은 구조로 있다.

## 0. 한 줄

**세션을 원문으로 보존하고 그 위에서 모델이 grep으로 읽게 하는 것이 증류한 지식을 벡터로 꺼내는 것보다 낫다** — 문헌이 예측했고
(docs/research/agent-memory-axes-v1.md §3), 우리 하네스에서 240문항 대응 비교로 확인했으며(raw+explorer 36.2%·재실행 40.0% 대
raw+vector 25.8%, p=0.003·p<0.001), 그래서 v1 상품의 핵심은 원문 보존 + 탐색기이고 증류 runbook은 보조다.

## 1. v1이 만드는 것

Claude Code나 Codex에 훅 넷과 MCP 서버 하나를 붙이면:

1. **세션이 남는다.** 모든 스텝이 로컬 스토어에 원문으로, 어느 프로젝트·브랜치·시각의 것인지(origin)와 함께.
2. **세션이 경험으로 증류된다.** 세션당 모델 호출 한 번으로 runbook — 과제·결과·실패·사용자의 교정·절차 — 이 나오고, 근거 스텝을 가리킨다.
3. **다음 세션이 받는다.** 같은 프로젝트에서 세션 시작 시 지난 작업이, 프롬프트마다 관련 runbook과 지난 턴이 주입된다. 다른 프로젝트의
   기억은 섞이지 않고, 같은 과제의 새 runbook이 옛 것을 대체한다.
4. **깊이 필요하면 모델이 원문을 뒤진다.** MCP `research_memory`가 탐색 에이전트를 돌려 트랜스크립트를 grep·read하고 인용된 답을 돌려준다.
5. **압축에도 잃지 않는다.** 압축 직전에 트랜스크립트가 보존되고, 압축 뒤 이 세션이 말했던 것이 되돌아온다.
6. **두 호스트, 한 스토어, 상시 경로 LLM 0콜.** 임베딩은 로컬, 지출은 세션당 증류 한 번(9B 기준 세션당 약 $0.002).

v1이 아닌 것: 대화형 사실 메모리(Mem0류), KV·파라메트릭 기질, RL 정책.

## 6. 아직 확정하지 못한 것

- **실행 간 분산은 쟀다.** raw+explorer를 같은 스토어·같은 설정으로 다시 돌려 40.0%(1차 36.2%)를 얻었다. 아암 내 분산이 약 4pp이므로
  "탐색기 > 벡터"(두 실행 모두 p≤0.003)는 분산 밖이고, "raw+explorer > experience+explorer"(6.6·10.4pp, p=0.064·0.005)는 두 실행에서 같은
  방향이지만 증류 아암은 한 번만 돌렸으므로 그 크기는 아직 확정하지 않는다. 증류가 탐색을 **돕지 않는다**는 것까지만 말할 수 있다.
- **judge 비용**은 GPT-5.2(OPENAI 키)로 별도 청구되어 위 표에 없다.
- **enterprise 도메인**은 raw 저장본만 구축했고 채점하지 않았다.
- **논문 베이스라인을 우리가 다시 돌리지 않았다.** 리더보드 수치를 그대로 쓴다.

- **긴 세션의 증류 범위.** 증류 프롬프트는 트랜스크립트를 머리 2/3 · 꼬리 1/3로 잘라 `max_chars` 안에 넣는다. §8의 세션(1,095스텝)에서
  runbook 3건이 인용한 스텝은 0–47과 1058–1088뿐이고, 가운데 1,000스텝(LME-V2 측정·묶음 B·의미 축 구현)은 증류에 보이지 않았다.
  수치: 이 세션을 렌더하면 919,802자(약 230K 토큰)이고 `max_chars` 60,000에서 보이는 것은 73스텝, **6.0%** 다(0–47과 1196–1220).
  60,000자 구간으로 나누면 16콜이며 9B 가격으로 입력 $0.023 + 출력 약 $0.004, 세션 하나에 **약 $0.03** 이다. 세션당 1콜 원칙은
  보통 세션(60,000자 이하, 1콜)에서는 그대로 성립하고, 며칠짜리 세션에서만 "1콜"과 "전부 본다"가 갈린다. **조치**: 기본은 1콜 그대로,
  `[write] distill_max_calls = N`이면 렌더가 필요로 하는 만큼(최대 N)의 연속 구간으로 나눠 구간마다 한 번 부른다. 스텝 라벨은
  세션 전체 번호라 어느 구간의 인용이든 같은 에피소드를 가리키고, 구간이 보여 주지 않은 스텝의 인용은 전과 같이 거부된다. 우리
  도그푸드 설정은 8로 둔다(세션당 최대 약 $0.02). 어느 쪽이든 원문은 에피소드로 전부 남아 탐색기가 뒤질 수 있다(§0의 순위가
  여기서도 유지된다).

**구간별 증류 첫 실전(같은 날, `distill_max_calls = 8`)**: 세션이 1,326스텝으로 자란 뒤 `distill` 훅을 다시 쏘자 데몬이 자란 세션으로 판정해
전 스텝을 다시 보존하고 8구간·8콜로 증류했다(약 6분, 9B 기준 약 $0.02). 결과는 아래와 같고, 1차의 runbook 3건은 은퇴되었다.

| | 1콜(1차) | 8구간 |

| runbook | 3 | 34 |
| 인용 스텝 합집합 | 73 / 1,221 (6.0%) | 415 / 1,326 (31.3%) |

구간 안의 과제가 잘게 쪼개져(예: "Run full test suite after refactoring", 1스텝 인용) 시작 블록 5건이 한 세션 안에서 임의 순서가 되는 문제가
드러났고, 세션 안에서는 스텝 범위 역순으로 정렬하도록 고쳤다. `stage:other`가 늘어난 것은 구간 프롬프트에서 모델이 단계를 덜 판단한다는
신호이며, 절차 속성(#4)의 품질 문제로 남긴다.

다른 프로젝트 cwd의 게이팅은 데몬 경로와 폴백 경로 모두 빈 결과로 확인했다. 새 세션의 SessionStart(startup) 실행 자체는 Claude Code가 부르는 것이라
이 세션에서는 훅 출력까지만 확인했다.
